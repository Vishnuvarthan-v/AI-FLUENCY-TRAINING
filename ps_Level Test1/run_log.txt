Your task_agent.py is the main Python file for an Agentic RAG Helpdesk.
- RAG — AI searches your college handbook and uses the retrieved information to answer questions.
- Agent — AI decides which tool to call to answer a question.
- LangGraph — Controls the agent's workflow, including tool calls and repeated reasoning steps.
- Memory — Allows the conversation to retain earlier messages within the same conversation thread.
1. Run task_agent.py
Python starts executing the file

2. Ask the AI a question
Example: What is the late fee?

3. AI decides which tool is needed
Handbook search, fee lookup, calculator, etc.

4. Tool executes and returns a result
Python runs the tool and returns its output

5. AI generates the final answer
LangGraph may repeat the tool step if needed

Evaluates supported arithmetic expressions.
Example: 18000 + 15000 returns 33000.



The @tool decorator makes an eligible Python function available to the language model as a tool. The model can request a tool call, but Python executes the function and returns the result.

The key part is this loop:
Agent → Tool → Agent
Suppose you ask for the combined fee of two courses.
1. The agent decides which course-fee tools to call.
2. The tools return the individual fees.
3. The agent may call the calculator to add them.
4. The agent uses the returned results to formulate the answer.
5. If it requests no more tools, the graph ends.
This is why an agent is different from a simple chatbot that only generates text.
Section G — Compile the graph and enable memory
Your code uses InMemorySaver() as a checkpoint saver when compiling the graph. It then calls the graph using a thread_id.
A simplified example:
checkpointer = InMemorySaver()graph = builder.compile(checkpointer=checkpointer)



Your actual graph and function names may vary slightly, but the important concept is the same.
The thread ID identifies a conversation:
ask(question, "task-run")



If you use "task-run" for multiple questions, the graph can use that thread's saved messages as conversation context.
For example:
- Question 1: "What is the late fee?"
- Question 2: "And what is the maximum?"
The second question can refer to the late-fee answer from the first question.
But if you use "student-1" and "student-2" as separate thread IDs, their conversation histories remain separate.
Memory limitation: InMemorySaver keeps checkpoints in RAM. Do not assume the conversation will survive restarting the Python process.
